# Практическая работа № 3

Вариант № 5.

## Описание проекта

Проект реализует ассемблер и интерпретатор учебной
виртуальной машины (УВМ) на языке Python.

Программа разрабатывается поэтапно.

На первом этапе реализованы:
- чтение программы на языке JSON;
- проверка корректности команд;
- преобразование JSON в промежуточное представление;
- интерфейс командной строки;
- тестовый режим вывода полей A, B и C;
- автоматические тесты.

На втором этапе реализовано формирование машинного кода.
Интерпретатор будет добавлен на следующих этапах.

## Команды виртуальной машины

Вариант № 5 предусматривает четыре команды:

| Операция | Код A | Размер B | Размер C |
|---|---:|---:|---:|
| load_const | 98 | 32 бита | 3 бита |
| read_mem | 125 | 3 бита | 13 бит |
| write_mem | 65 | 3 бита | 3 бита |
| bit_not | 50 | 13 бит | 13 бит |

Каждая машинная команда должна занимать 6 байт.

## Формат входной программы

Ассемблер принимает JSON-массив объектов.

Каждый объект содержит:
- op — название операции;
- b — значение поля B;
- c — значение поля C.

Код операции A определяется по имени команды.

Пример:

    [
      {"op": "load_const", "b": 7, "c": 2},
      {"op": "read_mem", "b": 0, "c": 173}
    ]

Полный пример из спецификации находится в файле:

    examples/specification.json

## Структура проекта

- src/uvm/main.py — интерфейс командной строки

## Основные функции

### instructions.py

- validate_field() — проверяет диапазон поля.
- parse_instruction() — проверяет одну команду.
- parse_program() — преобразует JSON в список команд.

### main.py

- parse_arguments() — обрабатывает аргументы запуска.
- load_instructions() — загружает JSON-программу.
- print_instructions() — выводит поля команд.
- main() — управляет запуском ассемблера.

## Подготовка окружения

Создать виртуальное окружение:

    python3 -m venv .venv

Активировать:

    source .venv/bin/activate

Установить инструменты разработки:

    python -m pip install -r requirements-dev.txt

## Запуск ассемблера

Показать справку:

    ./run.sh --help

Запустить тестовый режим:

    ./run.sh --input examples/specification.json --output output/specification.bin --test-mode

Аргументы:
- --input — путь к JSON-программе;
- --output — путь к двоичному файлу;
- --test-mode — показать поля A, B и C.

Ассемблер создаёт двоичный файл по пути --output.
Каждая команда кодируется шестью байтами.

## Автоматические тесты

Запустить тесты:

    PYTHONPATH=src python -m unittest discover -s tests -v

## Проверки качества

Проверка PEP 8 и импортов:

    python -m ruff check src tests

Проверка цикломатической сложности:

    python -m radon cc src tests -s -n C

Требования к качеству:
- длина функции не более 40 строк;
- цикломатическая сложность не выше 10;
- имена соответствуют PEP 8;
- строки Python не длиннее 79 символов.

## Этап 2. Формирование машинного кода

Реализовано кодирование четырёх команд УВМ в двоичный
формат. Каждая команда занимает ровно 6 байт.

Для расположения полей используется битовая упаковка.
Порядок байтов — little-endian.

Кодирование реализовано в файле:

    src/uvm/encoding.py

Создать двоичный файл:

    ./run.sh --input examples/specification.json --output output/specification.bin

Просмотреть машинный код:

    xxd -g 1 -c 6 output/specification.bin

Эталонные последовательности для варианта № 5:

    load_const: 62 07 00 00 00 02
    read_mem:   7d 68 05 00 00 00
    write_mem:  41 22 00 00 00 00
    bit_not:    32 cc 82 70 00 00

Размер программы из четырёх команд составляет 24 байта.

Проверки второго этапа:

- сравнение машинного кода с четырьмя эталонами;
- проверка граничных значений полей;
- запрет перезаписи исходного JSON;
- создание отсутствующих каталогов для результата;
- обработка ошибок чтения и записи;
- проверка отсутствия бинарника при ошибочном JSON.
